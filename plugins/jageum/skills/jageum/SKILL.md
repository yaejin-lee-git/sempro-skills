# 자금수지보고 만들기

담당자는 코딩을 모른다고 생각하고 쉬운 말로, 한 번에 하나씩 묻는다. 숫자는 전부 스크립트가 나스 파일에서 가져오고, Claude는 실행, 확인, 설명, 비고 문장만 맡는다. 답은 한국어로 짧게.

## 스크립트 부르는 법
이 스킬 폴더의 `scripts/jageum.py`. 항상 이렇게 (윈도우, 맥 같음):
```
uv run --with openpyxl python "<이 스킬 폴더>/scripts/jageum.py" <명령> ...
```

## A. 첫 설정 인터뷰
`status`가 "설정이 없습니다"이거나 담당자가 처음 설정을 원하면, 보고서를 만들기 전에 이것부터 한다. 각 단계는 Claude가 먼저 직접 확인하고, 안 되는 것만 담당자에게 묻는다.

1. **인사와 안내**: "자금수지보고 첫 설정을 하겠습니다. 다섯 가지만 확인할게요. 5분쯤 걸립니다."
2. **uv 확인**: `uv --version`을 실행한다.
   - 없으면: "보고서를 만드는 프로그램 실행 도구(uv)를 설치해야 합니다. 제가 설치해도 될까요?" 허락하면 윈도우는 `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`, 맥은 `curl -LsSf https://astral.sh/uv/install.sh | sh`. 설치 뒤 "Claude 앱을 완전히 껐다 켠 다음 '자금수지 설정 이어서 해줘'라고 말해 주세요"라고 하고 멈춘다.
3. **나스 연결 확인**: `find-nas`를 실행한다.
   - 후보가 하나면 "나스 폴더가 여기 맞나요? <경로>"라고 확인한다.
   - 여러 개면 번호를 붙여 고르게 한다.
   - 없으면 묻는다: "이 PC에 시놀로지 드라이브(나스)가 연결돼 있나요? 파일 탐색기에서 자금마감 보고 폴더가 보이는 곳의 주소를 복사해 붙여 주세요." 연결이 안 돼 있다고 하면 "시놀로지 드라이브 연결은 실장님께 요청해 주세요"라고 안내하고 멈춘다.
4. **폴더 구조와 쓰기 확인**: `check --nas "<경로>"`.
   - `보고서폴더`가 없으면 경로가 맞는지 다시 묻는다.
   - `보고서폴더에쓰기가능`이 false면 "나스가 내려받기 전용으로 연결돼 있어 보고서를 저장할 수 없습니다. 시놀로지 드라이브에서 이 폴더를 양방향 동기화로 바꿔야 합니다. 실장님께 요청해 주세요"라고 안내한다(설정은 계속 진행).
   - `원자료폴더`가 없으면 "원자료 폴더가 아직 없습니다. 셈프로가 넣어 주는 폴더라 처음엔 없을 수 있습니다"라고만 말한다.
5. **담당 지점**: `지점폴더` 목록을 번호로 보여 주고 "어느 지점을 맡고 계세요? 여러 개면 번호를 모두 말해 주세요."
6. **회사 이름**: "통합 보고서 제목에 쓸 회사 이름을 알려 주세요 (예: ○○산업)." 모르겠다고 하면 비워 둔다.
7. **저장**: `config --nas "<경로>" --branches "<지점들>" --company "<회사>"`.
8. **시험 확인**: 맡은 지점 하나로 지난달 기준 `where`를 돌려 보고, 찾은 파일을 쉬운 말로 알려 준다 (분개장, 통장거래, 지난달 보고서가 있는지). 없는 게 있으면 무엇이 없는지 말한다.
9. **끝 안내**: "설정이 끝났습니다. 매달 위하고에서 통장 전표 처리를 끝내면 '자금 확정했어, 10월 <지점> 자금수지 해줘'라고 말해 주세요."

## B. 매달 보고서 만들기
1. **확정 확인**: 담당자가 자금을 확정했다고 말하지 않았으면 한 번만 묻는다. "위하고 통장 전표 처리와 프로젝트 확인을 끝냈나요?" 지점과 월은 말에서 정한다. 월이 없으면 지난달. 지점이 없으면 설정의 `내지점`이 하나면 그 지점, 여러 개면 묻는다.
2. **파일 확인**: `where --branch <지점> --ym <연-월>`. 원자료가 없으면 원자료 폴더 경로를 알려 주고 "셈프로가 아직 원자료를 넣지 않았습니다. 실장님께 확인해 주세요"라고 하고 멈춘다. 지난달 보고서가 없으면 그 사실을 알리고 멈춘다.
3. **만들기**: `report --branch <지점> --ym <연-월>`. 담당자가 "오늘자", "○일 기준"처럼 월 중간 보고서를 원하면 `--day <일>`을 붙인다. 원자료는 매일 아침 수집분이라 통장은 전날까지, 분개장은 그 전날까지 들어 있으니, 오늘자면 어제 날짜를 기준일로 하고 그 점을 알려 준다. 이미 담당자 보고서가 있으면 덮지 않고 이름 끝에 `(셈프로)`를 붙여 저장된다. 담당자가 덮어써도 된다고 분명히 말한 경우에만 `--force`.
4. **확인할것 설명** (없으면 "걸린 것 없음"):
   - `분류확인`: 분류가 거래와 어긋나 보이는 줄. **엑셀에서 고치지 말고 위하고 전표의 프로젝트를 고친 뒤 "다시 해줘"라고 하라고** 안내한다.
   - `통장만`, `계좌`: 통장에는 있는데 분개장에 없는 거래(전표 처리 전)와 그 때문에 생긴 잔고 차이. 날짜, 적요, 금액을 보여 주고 위하고에서 처리한 뒤 다시 하라고 한다.
   - `프로젝트없음`: 프로젝트가 빈 보통예금 줄. 위하고에서 붙이고 다시.
   - `양식계좌번호다름`: 지난달 보고서의 계좌번호가 위하고 계좌와 다름. 숫자는 위하고 계좌로 맞췄으니 알려만 준다.
   - `양식에없는계좌`: 위하고에 거래가 있는데 보고서에 줄이 없는 계좌. 담당자가 줄을 추가할지 정한다.
5. **비고 쓰기**: `분류합계`에서 금액이 있는 분류마다 한 줄 (대체거래는 비움). `지난달비고`의 말투와 길이를 따르고 `분류별큰거래`의 큰 것만 넣는다. 짧게, 거래처 여럿은 `·`로 잇는다. 지어낸 내용은 넣지 않는다. 키는 `"영업입금(입금)"`, `"비용지출(출금)"`처럼 분류(입금/출금). json 파일로 저장해 `notes --report <보고서> --notes <json>`. 넣은 비고를 보여 주고, 고쳐 달라면 다시 넣는다.
6. **마무리 안내**: 보고서 경로와, 엑셀로 열어 저장 전에 볼 네 곳.
   1) 자금수지 시트 E2, F2 = TRUE  2) 계좌마감 차이 칸 = 0  3) 계좌마감 입출금 대조 칸(J열) = 0  4) 비고
7. **다시 해줘**: 위하고를 고쳤다고 하면 B-2부터 다시.

## C. 통합
"통합" 요청이면 `total --ym <연-월>`. `합계`(보통예금, MMF·신탁, 총계)와 `빠진지점`(아직 보고서를 안 만든 지점)을 알려 준다.

## 지켜야 할 것
- 숫자를 지어내거나 엑셀 값을 손으로 고치지 않는다. 모든 숫자는 스크립트로만.
- 위하고에 접속하지 않는다. 나스 파일만 읽는다.
- MMF, 신탁(기타단기금융상품) 계좌는 보통예금 원장이 아니라 통장 입출금을 따로 적어 합산한다 (스크립트가 처리). 자금수지 시트에는 보통예금 줄만 들어간다.
- 지점마다 다른 양식, 수식, 메모는 지난달 보고서 그대로 둔다 (스크립트가 처리).
- 명령을 실행하기 전에 무엇을 하는지 한 줄로 말한다. 오류가 나면 오류 문장을 쉬운 말로 풀어 주고, 담당자가 할 일만 알려 준다.
